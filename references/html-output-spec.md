# HTML 交付规范

## 文件要求

- 生成一个 UTF-8、响应式、可独立打开的 `.html` 文件。
- 默认将内容、样式和必要脚本内联，避免依赖构建工具。
- 如果图表依赖外部库，必须同时保留可读的文本或 Mermaid 源码作为降级方案。
- 视觉服务于证据和层级，不加入无关品牌装饰。

## 必备章节

1. 执行摘要；
2. 产品类型、主路径和拆解重心；
3. 查看范围、证据登记、证据缺口；
4. 用户层；
5. 技术层；
6. 模型层；
7. 数据层；
8. 跨层端到端流转；
9. 当前架构 As-Is；
10. 建议架构 To-Be；
11. 风险与优先级；
12. 架构组件与证据追溯；
13. 未知事项与补证计划。

产品类型需要时增加 Agent 契约、资产谱系、ER 图、时序图或模型能力表。

## 图表规则

- 流程图标注触发、读取、写入、调用、确认、事件、状态更新和资产引用。
- 区分已确认、合理推断、建议设计和未知，并提供图例。
- As-Is 和 To-Be 分开绘制或分栏展示。
- Mermaid 图保留源码，便于复核和再编辑。
- 大图支持横向滚动或自动缩放，不能让普通读者只能看到局部。

## 表格规则

- 证据列写具体页面原文、控件、文件、URL 或代码位置。
- 不把推断写进页面事实单元格。
- 大表设置横向滚动和粘性表头。
- 风险表包含影响、触发条件、证据、优先级和建议缓解。

## 验证清单

交付前验证：页面标题正确；章节顺序完整；表格行数与数据一致；图表成功渲染或有可读降级；控制台无未处理错误；桌面和窄屏均可阅读；本地文件链接有效；报告中不存在未替换模板文本；任何厂商、模型、后端或数据库结论都有证据标签。
